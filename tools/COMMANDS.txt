================================================================================
 COMANDOS DE LAS TOOLS  —  FireEmblem4_5_Remake/tools
================================================================================
Todas se lanzan desde la RAÍZ del repo. Los generadores resuelven sus rutas
relativas a su propia ubicación, así que el cwd no importa salvo para los
argumentos que pases a mano.

Los build_* que leen de LT-maker tienen rutas por defecto de la máquina del
autor (D:\FEHW\lt-maker-moded\*.ltproj); en otra máquina hay que pasar las
rutas como argumentos.


================================================================================
 1) AUDITORÍA  (solo lectura — no modifican nada)
================================================================================

# Matriz de cobertura de assets (map sprites + combat anims + retratos).
# Cruza classes.json / units.json contra assets/. Salida: docs/ASSET_COVERAGE.{xlsx,md}
python tools/asset_coverage.py            # genera .xlsx + .md (por defecto)
python tools/asset_coverage.py --no-md    # solo el .xlsx
python tools/asset_coverage.py --no-xlsx  # solo el .md   (no requiere openpyxl)

# Integridad referencial classes <-> units <-> map_sprites/ <-> combat_anims/.
# Lista referencias colgantes y assets huérfanos. Salida: consola.
python tools/audit_wiring.py

# Auditoría global: TODA la data (units/classes/items/skills/weapons) contra
# TODOS los assets (retratos, sprites, anims, iconos, audio).
# Salida: consola + docs/RESOURCE_AUDIT.md
python tools/resource_audit.py


================================================================================
 2) GENERAR DATA DESDE LOS .ltproj  (fuente de verdad: LT-maker)
================================================================================

# TODO-EN-UNO: regenera classes/weapons/items/skills/units + tablas por juego
# desde el game_data de ambos .ltproj. Reemplaza a build_data_from_spreadsheet
# + build_units.
python tools/build_from_lt.py [fe4_ltproj_dir] [fe5_ltproj_dir] [out_data_dir]

# Unifica los units.json de FE4 y FE5 en data/general/units.json.
python tools/build_units.py <fe4 units.json> <fe5 units.json> <outdir>

# Herencia gen 2 (FE4): convierte data/general/gen2_inheritance_source.json
# (cosecha de fireemblemwod) en data/general/gen2_children.json con el modelo
# BASE + MODIFICADOR-POR-PADRE que consume SubstituteSystem.
python tools/build_gen2_children.py

# Excel de referencia de la herencia gen 2 (una hoja por hijo: máximos, base,
# growths y desglose por padre) -> docs/FE4_Gen2_Inheritance.xlsx
python tools/build_gen2_xlsx.py

# Genera data/<game>/levels/*.json (mapas/despliegues) desde los .ltproj.
python tools/build_levels.py [fe4_ltproj] [fe5_ltproj] [out_data_dir]

# Genera data/<game>/events/events.json desde los eventos del .ltproj.
python tools/build_events.py --fe4 "<GotHW.ltproj>/game_data/events.json" \
                             --fe5 "<Thracia776.ltproj>/game_data/events.json"

# Genera data/<game> tilemaps desde los tilemap.json exportados.
python tools/build_tilemaps.py [fe4_tilemap.json] [fe5_tilemap.json] [out_data_dir]

# Genera data/general/portrait_offsets.json (offsets de parpadeo/boca) desde
# los portraits.json de los .ltproj.
python tools/build_portrait_offsets.py \
    --fe4 "<GotHW.ltproj>/resources/portraits/portraits.json" \
    --fe5 "<Thracia776.ltproj>/resources/portraits/portraits.json"


================================================================================
 3) GENERAR / SINCRONIZAR DESDE EL SPREADSHEET (Genealogy + Thracia .xlsx)
================================================================================

# Genera data/general desde el .xlsx (fuente antigua; hoy preferir build_from_lt).
python tools/build_data_from_spreadsheet.py "<ruta al .xlsx>" [outdir]

# Sincroniza bases/caps/growths/mov/con/rangos de clase desde el .xlsx a
# classes.json. Preserva id/name/desc/tier/promotion/skills/sprites.
# Por defecto es DRY-RUN (no escribe); usa --write para aplicar.
python tools/sync_classes_from_xlsx.py            # dry-run (solo muestra cambios)
python tools/sync_classes_from_xlsx.py --write    # aplica los cambios

# Setea el modelo BASE + versions{FE4,FE5} en classes.json (nivel superior =
# SAGA; versions.FE4/FE5 sobreescriben por-stat los 8 stats de combate).
# Idempotente. Sin argumentos (rutas fijas).
python tools/set_class_versions.py

# Proporcionalidad FE4<->FE5 por clase desde los bloques versions de
# classes.json. Salida: data/general/class_proportions.json + docs/*.xlsx
python tools/build_class_proportions.py

# Excel de referencia de clases (FE4/FE5) desde game_classes_wod_source.json.
# Salida: docs/FE4_FE5_Classes_Real.xlsx
python tools/build_game_classes_xlsx.py


================================================================================
 4) ASSETS
================================================================================

# Genera la animación "Unarmed" (Stand/Dodge/Miss) desde un sheet existente.
python tools/build_unarmed.py <carpeta_de_una_anim>          # una anim
python tools/build_unarmed.py <raíz_de_anims> --recursive    # todas (recursivo)
python tools/build_unarmed.py <carpeta> --force              # regenera aunque exista
python tools/build_unarmed.py <carpeta> --dry-run            # no escribe; solo lista

# MAP SPRITES: convierte sprites de origen (fondo verde LT 129,160,128) al
# formato del proyecto: {clase}-stand.png (192×144) + {clase}-move.png (192×160).
# Formato GBAFE: idle y walk en columnas separadas; divide por nº de frames
# (stand=3, walk=15 → usa 12); right = espejo de left; ancla por pies (y=40).
# Salida por defecto: ./map_sprites en el DIRECTORIO ACTUAL.
python tools/build_map_sprites.py                      # LOTE recursivo del dir actual
python tools/build_map_sprites.py --batch <carpeta>    # lote de otra carpeta
python tools/build_map_sprites.py --name Cavalier \
    --src-stand ruta/Cavalier-stand.png --src-move ruta/Cavalier-walk.png   # una clase
python tools/build_map_sprites.py --src-move ruta/X-walk.png --inspect       # inspeccionar
#   Ajustes útiles: --walk-order (def left,down,up) · --out <dir> · --raw-names

# BITMAP FONTS: convierte sprite-fonts LT (.idx + .png) a BMFont .fnt, que Godot
# importa como FontFile. Salida por defecto: assets/GBA/fonts/bmp/
python tools/build_bitmap_font.py --src <carpeta_ltfonts>            # lote (color white)
python tools/build_bitmap_font.py --src <carpeta> --name text        # una fuente
python tools/build_bitmap_font.py --src <carpeta> --color black --name reel  # otro color
